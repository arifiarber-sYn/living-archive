# The incident this agent is built against (12–13 October 2026)

This is the source for the "what a wrong answer costs" paragraph in the README. It is the author's own operations, not a hypothetical.

## What happened

- **12 Oct 2026, 15:02** — a submission form for an unrelated event was sent to a third party. The confirmation ("Submission received") was recorded in a journal file — one line among dozens — and in a folder named after the submission date. It was **not** recorded in the state file that the author's agents read first.
- **13 Oct 2026, 09:25** — the next morning, two agents (one human-directed, one autonomous) both read the state file, found no record of a submission, and treated it as still pending. The author was asked to approve "the final click", approved it, and the **same form was submitted a second time** — identical content, same PDF hash — against a page that says "one submission per project".
- The duplicate had to be disclosed and explained to the organiser.

Nothing was lost except credibility and a morning. That is the cheap version of this failure class. The expensive version is acting twice on a payment, a cancellation or a legal deadline.

## Root cause, as recorded

1. **A fact that lived in only one place**, and not in the place that is read first. Memory that is not where you look is memory you do not have.
2. **The check lived outside the action.** A "has this already been done?" guard existed as a separate tool and was not invoked by the script that actually performed the action.

## What changed on the operations side

- A registry of irreversible external actions (submit / pay / publish / email), consulted **inside** the script that performs the action, fail-closed: if the key is already registered, the script refuses.
- Rule: a completed irreversible action is written to the registry and to the state file in the same turn — a note that exists only in a journal does not exist for the next turn.

## What that has to do with this project

The Living Archive is the agent-side answer to the same failure class:

- every memory unit is a **file with a source, a date and a git commit** — not a line in a chat log;
- `make audit ID=<unit>` answers *what / source / when / who / how to revert / is it indexed* from files and git alone;
- every answer **cites a unit or refuses** — a confident answer with no source is exactly what caused the second click.

Dates and times are from the author's git history and journal; the third party and the event are deliberately not named.
